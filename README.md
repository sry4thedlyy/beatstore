# Beatstore

Демонстрационный интернет-магазин битов и драмкитов: русский интерфейс, цены в рублях, один продавец.

Реализована первая итерация: каталог из PostgreSQL, поиск по названию, страницы товаров, обложки и миниатюры, общий MP3-плеер, варианты лицензий и условия. Начальные цены MP3/WAV/STEMS — 1 000/2 000/3 000 ₽; скидка применяется к обычным лицензиям, цена эксклюзива задаётся отдельно.

Также реализованы регистрация по email и паролю, вход, выход, восстановление пароля через локальную почту и начальный личный кабинет. Роль администратора определяется сервером; его кабинет показывает сводку каталога.

Кабинет администратора поддерживает создание, редактирование, публикацию и снятие товаров с публикации, загрузку файлов. Оформление заказа, тестовые платежи, выдача покупок и документов, Yandex Object Storage ещё не подключены.

## Локальный запуск

Требуется Node.js 22.20 или новее совместимой версии. Docker и отдельный PostgreSQL для первого запуска не нужны.

```sh
npm ci
npm run auth:setup
npm run db:setup
npm run dev
```

Открыть [локальный каталог](http://127.0.0.1:3000). Если порт занят, сначала остановить другой экземпляр приложения. Сервер останавливается сочетанием Ctrl+C в терминале.

`db:setup` создаёт таблицы, генерирует демонстрационные файлы и добавляет два бита и два драмкита. Повторный запуск не дублирует товары и не отменяет их редактирование. Запускать команды базы **при остановленном приложении**: локальную PGlite-базу может открывать только один процесс.

База находится в `.data/postgres`, файлы — в `.data/demo-assets`. Эти папки, секреты и установленные зависимости не попадают в Git. Четыре коротких аудиопримера синтезируются программно; это тестовые материалы, не авторский каталог продавца. Архивы STEMS и проекта содержат демонстрационные заглушки; FLP-проекта в тестовом ZIP нет. Перед реализацией выдачи покупок их нужно заменить настоящими файлами.

`auth:setup` создаёт случайный секрет авторизации и адрес приложения в `.env.local`, сохраняя существующие значения. Остальные настройки используют значения по умолчанию; образец — [.env.example](.env.example). `.env.local` не включается в репозиторий.

При обновлении существующего проекта остановить приложение, выполнить `npm run auth:setup` и `npm run db:migrate`, затем снова запустить `npm run dev`. Рабочую базу удалять не требуется.

## Проверка аккаунтов локально

Вход доступен из шапки сайта. Регистрация запрашивает email, имя артиста или псевдоним и пароль длиной 12–128 символов. После регистрации открывается кабинет, после входа из карточки — исходный товар. Выход отзывает текущую сессию.

Для готового демонстрационного аккаунта при остановленном приложении:

```sh
npm run account:demo
```

Email — `demo@example.test`, пароль — `Beatstore-demo-2026`. Команда создаёт только локального покупателя и сохраняет данные уже существующего аккаунта.

Для проверки восстановления открыть «Не помню пароль» на странице входа и отправить запрос. Письмо сохраняется в `.data/mail`; настоящая отправка email пока не подключена. Прочитать последние письма можно **при работающем приложении**, поскольку команда не открывает базу:

```sh
npm run mail:inbox -- demo@example.test
```

Открыть ссылку из письма и задать новый пароль. Ссылка действует 30 минут, используется один раз и отзывает прежние сессии после успешной смены пароля. Письма содержат ссылки доступа и хранятся только в игнорируемой локальной папке, без публичного HTTP-маршрута. Файловая почта ограничена адресами `localhost`, `127.0.0.1` и `::1`; публичное размещение требует почтового сервиса.

Для назначения администратора сначала зарегистрировать аккаунт, остановить приложение, затем выполнить:

```sh
npm run account:admin -- owner@example.ru
npm run dev
```

Эту команду выполняет владелец локальной среды; публичного способа выбрать роль при регистрации нет.

## Управление товарами

Для отдельного демонстрационного администратора при остановленном приложении:

```sh
npm run account:demo -- --admin
npm run dev
```

Email — `admin@example.test`, пароль — `Beatstore-admin-2026`. Команда сохраняет пароль существующего аккаунта. Реальный аккаунт владельца назначается через `account:admin`; тестовые аккаунты предназначены для локальной демонстрации.

В кабинете нажать «Добавить товар», выбрать тип и название. Черновик виден только администратору. Заполнить поля и сохранить, затем выбрать файлы: каждый выбор запускает загрузку с прогрессом. Редактирование существующего товара открывается из его полной карточки. Кабинет содержит также снятые карточки и черновики.

Для бита нужны авторы, BPM, тональность, роялти, цена эксклюзива, требования к FL Studio и файлы MP3, WAV, ZIP дорожек и ZIP проекта с FLP. Базовые цены MP3/WAV/STEMS — 1 000/2 000/3 000 ₽. Для драмкита нужны цена, правила использования, MP3-превью и ZIP с текстовым файлом правил; текст должен соответствовать карточке. Скидка — до 99,99%, роялти — до 100%, не более двух знаков после запятой. Название — до 160 символов, авторов — до 20.

Обложка JPEG/PNG/WebP до 10 МБ становится квадратной: копии 1200×1200 и 480×480. MP3 — до 50 МБ, WAV — до 250 МБ, аудио — до часа. ZIP — до 500 МБ, без пароля и ссылок, до 10 000 записей и 2 ГБ после распаковки. Новые файлы находятся в `.data/uploads`. Объём готовых и загружаемых файлов, включая прежние версии, ограничен 1 ГБ и показан в кабинете.

Публикация проверяет комплектность на сервере. Прежние файлы сохраняются при замене; правка правил драмкита создаёт новую версию условий. Товар с покупками можно снять с публикации, но нельзя удалить. Удаление без покупок требует точного названия. Незавершённая оплата, резерв или проданный эксклюзив блокируют изменения. Устаревшая вкладка получает конфликт вместо перезаписи.

Ошибка или отмена загрузки убирает её временные файлы. После аварийного завершения процесса могут остаться `PENDING`-записи или служебные исходники; автоматическая уборка пока отсутствует. Готовые версии автоматически не удаляются.

## Проверки

```sh
npm run format:check
npm run lint
npm run typecheck
npm test
npm run build
```

Тесты используют отдельные базы в памяти и не меняют рабочую базу. Проверяются цены и округление, поиск и видимость товаров, готовность к публикации, неизменяемость условий, повторные покупки и уникальность эксклюзива после возврата, диапазоны байтов для перемотки аудио. Тесты авторизации проверяют регистрацию, хеширование паролей, email, роли, изоляцию аккаунтов, неверные и истёкшие сессии, CSRF, лимиты попыток, восстановление и отзыв сессий.

Тесты управления каталогом проверяют черновики и публикацию, конфликт версий, обработку обложек и длительность MP3, отклонение неверных аудио и ZIP, лимиты файлов и хранилища, прерывание загрузки, сохранность купленных файлов и условий при замене, удаление без покупок и запрет изменений при незавершённых заказах или проданном эксклюзиве. Файлы этих тестов создаются в отдельной временной папке.

Для запуска готовой сборки остановить режим разработки, затем выполнить `npm run build` и `npm start`.

## Устройство проекта

| Папка            | Назначение                                             |
| ---------------- | ------------------------------------------------------ |
| `src/app`        | Страницы Next.js, API авторизации и каталога, превью   |
| `src/components` | Формы аккаунта и товаров, карточки и общий плеер       |
| `src/domain`     | Расчёт цен и правила переходов без зависимости от базы |
| `src/server`     | Авторизация, запросы каталога, база и работа с файлами |
| `migrations`     | Версионируемые изменения структуры PostgreSQL          |
| `scripts`        | Подготовка базы и демонстрационных материалов          |
| `tests`          | Автоматические проверки правил и запросов              |
| `docs`           | Требования, архитектура и модель данных                |

Каталог и страницы товаров получают данные на сервере. Браузер получает только данные опубликованных карточек и управляет поиском, выбором лицензии и воспроизведением. Деньги считаются целыми копейками; входной текст поиска передаётся как параметр SQL, а не склеивается с запросом.

Миграция — последовательное изменение базы. Применённые миграции не редактируются: следующая правка создаёт новый файл. Контрольная сумма защищает от незаметной замены уже применённой миграции. Таблицы заказов, платежей и документов подготовлены, но сценарии покупки пока не реализованы.

## PostgreSQL и хранилище

По умолчанию используется PGlite — PostgreSQL в WebAssembly с сохранением на локальный диск. Это вариант для разработки в одном процессе. Полноценный сервер PostgreSQL подключается через `DB_DRIVER=postgres` и `DATABASE_URL`, используя те же SQL-миграции. Для него сначала создать отдельную пустую базу, настроить `.env.local`, затем выполнить `npm run db:setup`.

Драйвер обычного PostgreSQL предусмотрен, но проверка на отдельном сервере остаётся этапом подготовки публичного размещения. PGlite не проверяет гонки между несколькими соединениями: конкурентная продажа эксклюзива потребует дополнительных интеграционных тестов на обычном PostgreSQL.

Локальные файлы обслуживаются через `/media/<id>`: доступны только обложки, миниатюры и превью опубликованных товаров. WAV и ZIP не выдаются этим маршрутом. Бесплатный MP3 и превью могут содержать одинаковые байты; авторизация скачивания не может препятствовать сохранению публичного аудиопревью.

Yandex Object Storage предусмотрен архитектурой, но подключение бакета и ключей доступа относится к следующей итерации работы с файлами.
