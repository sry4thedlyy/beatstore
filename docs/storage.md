# Yandex Object Storage

## Режимы работы

По умолчанию `STORAGE_DRIVER=local`: демонстрация работает без облачного аккаунта. При `STORAGE_DRIVER=yandex` новые обложки, аудио, ZIP и PDF сохраняются в приватном бакете через официальный AWS SDK v3. Старые локальные версии продолжают читаться. Для чтения уже сохранённых облачных версий ключи, бакет и префикс должны оставаться настроенными, даже если новые файлы снова сохраняются локально.

База хранит идентификатор файла, бакет, ключ объекта, размер и SHA-256. Ключи генерируются сервером, включают UUID и не содержат имени покупателя или названия товара. SDK использует HTTPS-эндпоинт `https://storage.yandexcloud.net`, регион `ru-central1` и только явно заданный статический ключ; профили AWS и облачные роли компьютера не используются. Секреты остаются на сервере, без `NEXT_PUBLIC_` и передачи в браузер.

Публичные превью и защищённые покупки проходят через существующие маршруты магазина. Сервер проверяет доступ, затем передаёт объект потоком из S3 с поддержкой Range и HEAD. Для покупки сохраняются пятиминутный токен, сессия владельца и повторная проверка заказа. Прямые ссылки на S3 покупателю не выдаются: это сохраняет проверку доступа при возврате и прекращении бесплатного разрешения. CORS бакета для такого режима не нужен.

## Подготовка бакета

1. Создать аккаунт Yandex Cloud, платёжный аккаунт и каталог по [инструкции начала работы](https://yandex.cloud/ru/docs/storage/quickstart).
2. Создать отдельный [бакет](https://yandex.cloud/ru/docs/storage/operations/buckets/create) с уникальным именем, стандартным классом `STANDARD` и максимальным размером 1 ГБ. Чтение объектов, просмотр списка и чтение настроек должны быть доступны только авторизованным пользователям. Публичные ACL и политики не добавлять.
3. Для MVP оставить версионирование бакета выключенным: приложение само создаёт отдельный объект для каждой версии и сохраняет старые покупки. Не настраивать автоматическое удаление по сроку хранения.
4. Создать отдельный сервисный аккаунт и назначить `storage.editor` только на этот бакет. Создать его статический ключ доступа. [Подготовка SDK и ключей](https://yandex.cloud/ru/docs/storage/tools/aws-sdk-js).
5. Добавить настройки в игнорируемый `.env.local`. Значения ключей вводятся локально; их нельзя помещать в исходники, Git, документацию или переписку.

```dotenv
STORAGE_DRIVER=yandex
YC_STORAGE_BUCKET=имя-приватного-бакета
YC_STORAGE_PREFIX=beatstore
YC_STORAGE_ACCESS_KEY_ID=идентификатор-статического-ключа
YC_STORAGE_SECRET_ACCESS_KEY=секретный-ключ
```

Имя бакета должно быть DNS-совместимым. Префикс допускает латинские буквы, цифры, дефис, подчёркивание и разделители `/`, например `beatstore/demo`. Приложение поддерживает один облачный бакет; изменение бакета или префикса после переноса требует отдельной миграции расположений. При смене статического ключа сохраняются бакет и префикс.

## Проверка подключения

```powershell
npm run storage:check
```

Команда не открывает базу. Создаёт случайный временный объект размером 64 байта, проверяет PUT, HEAD, GET Range и отказ анонимному запросу. Затем удаляет только свой объект. Успешный результат содержит четыре значения `true`. Проверка подтверждает доступность и приватность этого объекта; отдельные публичные политики на другие пути нужно проверить в настройках бакета. При сбое удаления временный объект может остаться: сообщение требует восстановить доступ и проверить бакет. Секреты и подробности SDK не печатаются.

После изменения `.env.local` перезапустить приложение. Проверить загрузку файлов в редакторе, воспроизведение и перемотку аудио, тестовую покупку, ZIP и PDF. Проверка через настоящий Yandex Cloud требует созданного бакета и его ключей; автоматические тесты используют отдельный локальный S3 HTTP-сервер, без облачных расходов. Команды `test` и `test:postgres` принудительно выбирают локальное хранение и удаляют облачные настройки из окружения тестовых процессов; S3-сценарии получают тестовый клиент явно.

## Перенос существующих файлов

Остановить приложение перед импортом; PGlite допускает один процесс. Сохранить резервную копию базы, чтобы оставить прежние расположения файлов для восстановления. Затем выполнить:

```powershell
npm run storage:import -- --app-stopped
npm run dev
```

Перед открытием PGlite команда требует флаг `--app-stopped` и проверяет, что локальный порт приложения свободен. Это дополнительная проверка; все другие процессы, работающие с этой PGlite, также должны быть остановлены. Для обычного PostgreSQL импорт также выполнять при остановленном приложении.

Импорт копирует все готовые локальные версии, включая ранее приобретённые файлы и PDF. Размер и SHA-256 проверяются до загрузки; ссылка в `files` меняется только после успешной передачи и проверки метаданных. Идентификаторы файлов и документов, снимки заказов, условия и локальные оригиналы сохраняются. Частично завершённый импорт можно повторить: готовые ссылки пропускаются, уже записанный объект с подходящими размером и контрольной суммой используется повторно. Несовпадающий объект не перезаписывается. Миграции SQL и повторное наполнение базы для переноса не нужны.

Локальные оригиналы автоматически не удаляются. До переноса публичного сайта на другой сервер нужно завершить импорт и сохранить резервную копию базы; ссылки на оставшиеся локальные файлы требуют соответствующей папки `.data`.

## Запись, квота и сбои

Загрузка администратора сначала принимается потоком во временный локальный файл. Проверки аудио и ZIP и обработка обложки выполняются до отправки в S3. Только после успешной записи и повторной проверки версии карточки объект становится готовым в базе. PDF использует тот же облачный адаптер и аренду генерации. Старые версии не перезаписываются: каждый PUT содержит `If-None-Match: *`. Передача защищена `Content-MD5`, размером и метаданными SHA-256; HEAD подтверждает результат. При чтении сверяются размер и SHA-256, а GET использует ETag из HEAD в `If-Match`.

При ошибке удаляются только объекты той же операции, определяемой метаданными. Если удаление не подтверждено, запись `PENDING` сохраняет резерв квоты; её нельзя без проверки удалить вручную. Неподтверждённая запись, авария процесса или прерванный импорт могут оставлять служебные объекты. Автоматическая уборка ещё не реализована. Оплата и готовые покупки при сбое хранения сохраняются; PDF можно подготовить повторно.

Лимит базы — 1 ГБ с учётом сохраняемых версий и резервов. Локальные временные файлы также требуют свободного диска на сервере. Архив до 500 МБ передаётся потоком, но загрузка проходит через приложение; прямые загрузки браузера в S3 и возобновляемая загрузка не реализованы. Для публичного размещения нужны подходящие ограничения прокси, время выполнения запросов и дисковый бюджет. Передача скачивания также проходит через приложение, поэтому возможен трафик и у хостинга приложения.

Стандартное хранилище имеет бесплатный объём: первый 1 ГБ хранения, 10 000 операций записи и 100 000 чтения за месяц. Исходящий трафик тарифицируется отдельно с собственным бесплатным объёмом. Эти лимиты не делают весь хостинг бесплатным. Ограничение размера бакета и бюджетные уведомления помогают контролировать расход; уведомление само по себе не останавливает списания. Проверять [актуальные тарифы](https://yandex.cloud/ru/docs/storage/pricing) перед подключением.
