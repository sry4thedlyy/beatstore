# Резервные копии и восстановление

Копия создаётся для остановленного приложения с локальными файлами. Она содержит базу, `.data/demo-assets`, `.data/uploads`, `.data/documents`, `.data/owner-access` и `.env.local`, если эти пути существуют. Сохраняются прежние версии файлов и готовые PDF, а также аккаунты, покупки и снимки условий. Локальный почтовый ящик с временными ссылками восстановления, исходный код, зависимости и сборка в архив не входят. Вместе с копией сохраняется идентификатор коммита; код берётся из соответствующей версии репозитория.

Для PostgreSQL используется SQL-дамп `pg_dump --no-owner --no-privileges`; утилита должна поддерживать версию сервера. Для PGlite копируется закрытая база `.data/postgres`. Режим облачного хранилища отклоняется: эти команды не создают резервную копию S3-объектов.

## Создание

`npm run auth:setup` создаёт случайный `BACKUP_PASSPHRASE` в `.env.local`, сохраняя ранее заданный ключ. Нужен отдельный секрет не короче 16 символов, предпочтительно сгенерированное значение. Сохранить его в менеджере паролей или другом месте вне VPS **до удаления сервера**. Копии зашифрованы AES-256-GCM с ключом scrypt и случайными salt/IV. Без секрета восстановление невозможно.

Остановить приложение и все процессы, изменяющие базу или файлы. PostgreSQL как служба остаётся запущенным. На VPS остановить `beatstore`; локальный сервер завершить через Ctrl+C. Затем из корня проекта:

```sh
npm run backup:create -- --app-stopped
```

Команда дополнительно проверяет отсутствие слушателя на `127.0.0.1:3000` или на порту из `PORT`. Проверка порта не обнаруживает сторонние программы миграций или другой экземпляр на ином порту: их остановка остаётся обязательной.

Архив `.bsbackup` создаётся в `work/backups`, команда показывает путь и SHA-256. Сначала данные копируются во временную папку; после успешной упаковки или ошибки она удаляется. Нужен запас диска для исходных данных, временной копии и архива. Ограничения демоверсии — 8 ГиБ содержимого, 2 ГиБ на отдельный файл; рабочие загрузки магазина ограничены 1 ГБ в сумме. Символические ссылки и специальные файлы не допускаются.

Перенести архив на компьютер или другое независимое хранилище. Сверить SHA-256 и записать коммит (`git rev-parse HEAD`). Не отправлять `.env.local`, секрет или расшифрованную копию в Git. В архиве содержатся личные данные и настройки; доступ к нему и секрету ограничивается владельцем.

Копию делать перед обновлением и после каждого показа. Для долго работающего VPS нужен дополнительный регулярный график и независимое место хранения; автоматического расписания в данном профиле нет. Автоматические копии провайдера не заменяют проверенную копию вне удаляемого сервера.

## Распаковка и проверка

На компьютере или новом VPS подготовить код сохранённого коммита, установить зависимости. Указать прежний `BACKUP_PASSPHRASE` в локальных настройках; его нельзя заменять новым сгенерированным ключом. Выполнить:

```sh
npm run backup:restore -- --file=/absolute/path/to/beatstore.bsbackup
```

Создаётся **новая** папка `work/restores/restore-*`. Команда не заменяет рабочую базу, файлы и настройки приложения. Сначала проверяется аутентичность зашифрованного архива, затем пути, типы и размеры записей. Неверный секрет или повреждение завершают операцию ошибкой без пригодной частичной копии. Успешная расшифровка ещё не означает, что приложение восстановлено: нужно проверить базу и выдачу файлов.

Расшифрованная `.env.local` содержит настройки прежнего сервера. Не запускать с ней тестовую копию без изменения `DATABASE_URL` на **новую** базу, адреса магазина на loopback и `MAIL_DRIVER` на `file`. Иначе копия может обратиться к прежней базе или отправлять настоящие письма. Секрет авторизации сохраняется для переноса магазина; для изолированной проверки допускается новый секрет и новые сессии.

### PostgreSQL

Создать отдельную пустую базу для восстановления, например `beatstore_restore`, с владельцем `beatstore`. Не применять дамп поверх существующей базы. В Ubuntu команда администратора:

```sh
sudo -u postgres createdb --owner=beatstore beatstore_restore
psql -X --host=127.0.0.1 --username=beatstore --dbname=beatstore_restore --single-transaction --set=ON_ERROR_STOP=on --file=/absolute/path/to/restore-folder/database.sql
```

`psql` запрашивает пароль интерактивно; права нового приложения ограничены ролью `beatstore`. В команде указывается путь из результата распаковки. Для доступа пользователя к файлу каталог принадлежит владельцу запуска; не давать публичные права ради восстановления.

В отдельном клоне сохранённого коммита скопировать **восстановленную** `.data` и создать настройки с новым `DATABASE_URL`, `BETTER_AUTH_URL=http://127.0.0.1:3102`, `MAIL_DRIVER=file`, `PAYMENT_PROVIDER=demo`, `STORAGE_DRIVER=local`. Выполнить `db:migrate` при остановленном приложении: для того же коммита новых миграций быть не должно. Собрать приложение и запустить `npm start -- --port 3102`. Проверить прежнего покупателя, заказ, PDF и скачивание приобретённых байтов. При публичном восстановлении вернуть HTTPS и SMTP после успешной локальной проверки.

### PGlite

Для локальной копии использовать отдельный клон и восстановленную `.data` с `.data/postgres`. Указать `DB_DRIVER=pglite` и `PGLITE_DATA_DIR=.data/postgres`; запускать только одним процессом. Не открывать ту же папку тестовой копии одновременно из приложения и команды базы. Исходная рабочая база остаётся на месте. PGlite не используется в публичном профиле VPS.

## Удаление VPS

До удаления требуются архив вне VPS, отдельно сохранённый секрет, SHA-256, коммит и успешная проверка восстановления новой базы вместе с файлами. После этого владелец вручную удаляет сервер и ненужные платные связанные услуги в панели провайдера. Восстановление и удаление рабочей среды автоматически не выполняются.

Автоматические тесты проверяют реальную копию PGlite, сохранность записи и файлов, неверный секрет, повреждение архива и запрет копирования работающей базы. Отдельная проверка CI `backup-recovery` создаёт дамп PostgreSQL 16, восстанавливает его в новую тестовую базу и сверяет записи, хеш пароля, миграции и байты файла. Эти проверки не заменяют пробное восстановление конкретного архива владельца.

Технические источники: [pg_dump](https://www.postgresql.org/docs/current/app-pgdump.html), [psql](https://www.postgresql.org/docs/current/app-psql.html), [node-tar](https://github.com/isaacs/node-tar).
